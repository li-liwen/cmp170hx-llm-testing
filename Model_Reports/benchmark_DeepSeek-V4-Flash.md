# DeepSeek-V4-Flash-0731 on 4x CMP 170HX

**Model:** DeepSeek-V4-Flash-0731 (~284B total / ~13B active, MoE, DSpark speculative decoding)

**Hardware:** 4x NVIDIA CMP 170HX (GA100 sm_80, VRAM-unlocked 65536 MiB each, PCIe Gen2 x16)

## Run Configuration

Served via `dsv4-a100:devel` container (patched vLLM fork) on GPUs 0-3:

```bash
vllm serve /model \
  --served-model-name=deepseek-v4-flash \
  --pipeline-parallel-size=4 \
  --kv-cache-dtype=fp8 \
  --block-size=256 \
  --max-model-len=1048576 \
  --max-num-batched-tokens=2048 \
  --trust-remote-code \
  --gpu-memory-utilization=0.85   # 0.93 in production
  --max-num-seqs=8 \
  --no-enable-flashinfer-autotune \
  --tokenizer-mode=deepseek_v4 \
  --enable-auto-tool-choice \
  --tool-call-parser=deepseek_v4 \
  --reasoning-parser=deepseek_v4 \
  --speculative-config='{"method":"dspark","num_speculative_tokens":5}'
```

Key environment: `NVIDIA_VISIBLE_DEVICES=0,1,2,3`, `DSV4_LOGITS_ROW_CHUNK=64`,
`VLLM_PP_LAYER_PARTITION=12,12,12,7`.

## Notes / caveats

- These are engine-level numbers (single host, GPUs 0-3), not API-gateway numbers.
- The 1M-token context ceiling requires `DSV4_LOGITS_ROW_CHUNK=64` (upstream
  patch from this fork); without it the engine dies around ~134k tokens.
- Pipeline parallel (PP4) is required here — tensor parallel is arithmetically
  impossible for this MoE (64 heads / 256 experts) and 6.6x slower on prefill.
- Current rig re-verified 2026-08-31: container `dsv4-a100` healthy on GPUs 0-3,
  same engine settings, DSV4 still at ~110 tok/s aggregate decode.
